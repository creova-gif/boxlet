## Problem Statement

Developers building autonomous AI software engineers need to run untrusted code, install dependencies, run tests, and modify files inside isolated, resource-controlled environments. Today they glue together Docker, custom seccomp/capability policies, cgroup scripts, and external monitoring tools, or adopt a hosted microVM service like E2B without owning the execution core.

Existing open-source Rust runtimes (`youki` / `libcontainer`) target general-purpose container ecosystem parity rather than an agent-first programmable execution engine where policies, budgets, structured results, and future snapshotting/branching are first-class primitives.

Boxlet V1 solves the first layer of this stack: a minimal, real, secure Linux OCI container runtime and embeddable Rust crate that shares a single execution core across CLI and library callers, proves measurable isolation and cleanup on a fresh Linux host, and establishes clean trait seams for V2 programmable sandboxing and future filesystem checkpointing/branching.

## What Makes This Cool

- **Long-term "wait, it can do THAT?" moment (V2/V3 horizon):** Checkpoint an agent's execution environment, branch it into three independent sandboxes, let three agents explore competing fixes in parallel, compare their filesystem diffs and test results, and discard the losers without touching the original.
- **V1 proof-of-craft demo:** A short terminal recording on Linux where `boxlet run --memory 128m --cpus 0.5 --network none ./bundle` boots an OCI bundle, enforces a hard cgroup v2 memory limit, denies a prohibited syscall via pure-Rust seccomp BPF, emits a machine-readable `ExecutionResult` (bounded stdout/stderr, exit status, duration, CPU/memory usage, observable violation flags, cleanup status), and exits with zero orphaned processes or cgroups.
- **Zero-C-dependency static Linux builds:** Using AWS Firecracker's pure-Rust `seccompiler` plus a pure-Rust syscall table crate (`syscalls`) instead of C `libseccomp` means any fresh Linux machine can run `cargo build` with zero C header setup and ship clean static musl binaries.
- **Embeddable, policy-first Rust core:** Both the OCI CLI (`create`, `start`, `state`, `kill`, `delete`, `run`) and downstream Rust applications (such as Kora) drive the exact same `Engine`, `ExecutionPolicy`, and `ExecutionResult` API.

## Constraints

1. **V1 Scope Boundary:** Layer 1 minimal Linux OCI runtime + thin foundation for Layer 2 (`ExecutionPolicy`, `ExecutionResult`, replaceable trait seams).
2. **Explicit Exclusions for V1:** No checkpointing, no 3-way branching, no filesystem diffing (keep `RootfsProvider` seam ready), no rootless mode (root on a dedicated Linux 5.15+ host/VM is required in V1), no bridged/veth/CNI networking, no distributed scheduling, no multi-tenant control plane, no custom image registry, no GUI, and no claim of production-grade hostile multi-tenant isolation.
3. **Honest Security Posture:** Linux namespaces + cgroups v2 + capabilities + seccomp share the host kernel. V1 replaces the existing boilerplate `docs/THREAT_MODEL.md` with Boxlet V1's single-host, root-required, shared-kernel threat model and explicit non-goals, and keeps `IsolationBackend` replaceable so a Firecracker/`libkrun` or `youki` backend can plug in later without breaking callers.
4. **Engineering Standards (`AGENTS.md`):** Rust 2021+, `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo audit`, deterministic unit/integration tests, zero `.unwrap()` or `.expect()` in production paths, and ADRs in `docs/adr/` for every non-trivial design choice.
5. **Pragmatic Layer-1 Reuse:** Reuse `oci-spec` for `config.json` parsing, `nix` for Linux syscall wrappers, `caps` for capability dropping, `syscalls` for arch-specific syscall name-to-number resolution, and `seccompiler` for BPF filter compilation. Confine `unsafe` to a small, audited syscall module.

## Premises

1. **Shared Core + Replaceable Seams:** Boxlet V1 is a single Rust crate (`boxlet` lib + `boxlet` CLI binary) built around first-class `ExecutionPolicy`, `ExecutionResult`, `RootfsProvider`, `ResourceController`, and `IsolationBackend` abstractions, with a Linux namespace/cgroup v2/seccomp backend in V1.
2. **Pragmatic Layer-1 Reuse:** V1 reuses `oci-spec`, `nix`, `caps`, `syscalls`, and `seccompiler` rather than hand-rolling JSON schemas or raw syscall tables, isolating `unsafe` behind audited wrappers with zero `.unwrap()`/`.expect()` in production paths.
3. **Honest V1 Security Boundary:** V1 runs as root on a dedicated Linux 5.15+ host/VM, enforces `PR_SET_NO_NEW_PRIVS`, drops capabilities to an explicit allowlist, applies cgroup v2 memory/CPU/PIDs limits, loads an explicit seccomp profile (failing closed on unsupported fields/operators or unknown syscall names), and documents the shared-kernel boundary in a rewritten `docs/THREAT_MODEL.md`.
4. **Strict OCI Core + Ergonomic Wrapper:** V1 implements OCI lifecycle commands (`create`, `start`, `state`, `kill`, `delete`) first honoring `config.json` verbatim to pass `oci-runtime-tools` and lifecycle/cleanup tests, then layers `boxlet run --memory ... --cpus ... --network none ./bundle` on the exact same Rust `Engine`.
5. **Linux CI + Distribution Channel:** V1 ships with reproducible Linux CI (GitHub Actions `ubuntu-latest` running `rustfmt`, `clippy -D warnings`, `cargo-audit`, unit tests, and privileged Linux integration + `oci-runtime-tools` tests) plus a Linux release binary path (GitHub Releases musl binaries + crates.io-ready crate layout).

## Approaches Considered

### Approach A: Single-Crate Modular Runtime with `libseccomp`
Single Cargo crate (`boxlet` lib + `src/main.rs` CLI) with internal module seams and C `libseccomp` FFI for OCI seccomp rules. Rejected because requiring `libseccomp-dev` C headers adds friction on fresh Linux build hosts and complicates static release binaries, and raw post-`fork()` Rust code increases async-signal-safety risk.

### Approach B: Multi-Crate Workspace (`boxlet-core`, `boxlet-linux`, `boxlet-oci`, `boxlet-cli`)
Four-crate Cargo workspace separating portable SDK contracts from Linux syscalls at compile time. Rejected for V1 because four crates add upfront plumbing and error-mapping overhead before the first container boots; internal module + trait seams in a single crate can split cleanly into workspace crates in V2 once a second backend exists.

### Approach C: Policy-First Single Crate + Pure-Rust `seccompiler` + Self-Re-Exec Init (Selected)
Single Rust crate (`src/lib.rs` + `src/main.rs`) exposing portable `ExecutionPolicy`, `ExecutionResult`, `RootfsProvider`, `ResourceController`, and `IsolationBackend` traits alongside a Linux backend that uses pure-Rust `syscalls` + `seccompiler` (zero C dependencies) and a self-re-exec container init stage (`boxlet __init` coordinated over a Unix pipe/FIFO) instead of fragile post-`fork()` Rust state sharing.

## Recommended Approach

**Choose Approach C: Policy-First Single Crate + Pure-Rust `seccompiler` + Self-Re-Exec Init.**

- **Precedence & merge semantics (`create` vs `run`):**
  - `boxlet create` (and `Engine::create`) consumes the OCI bundle's `config.json` **verbatim** with zero opinionated defaults injected, preserving strict `oci-runtime-tools` compatibility.
  - `boxlet run` (and `Engine::run(bundle, policy)`) loads the bundle's `config.json` and overlays every explicitly specified `ExecutionPolicy` field (`memory`, `cpus`, `pids`, `network`, `capabilities`, `seccomp`, `timeout`, `max_output_bytes`) on top of the OCI spec. Any field omitted from both `ExecutionPolicy` and `config.json` receives Boxlet's safe V1 default (for example: `network = none`, `no_new_privs = true`, default-deny seccomp allowlist, 1 MiB output capture cap per stream).
- **Supported V1 network modes:**
  - `none` (default for `boxlet run`): creates an isolated Linux network namespace with loopback (`lo`) only and no external interfaces.
  - `host`: shares the host network namespace (no `CLONE_NEWNET`).
  - Bridged, `veth`, and CNI networking are explicitly excluded from V1; any unsupported network mode fails closed with a typed `BoxletError::UnsupportedNetworkMode`.
- **Bounded output capture & observable policy violations (`ExecutionResult`):**
  - `stdout` and `stderr` are captured into bounded buffers (default `max_output_bytes = 1 MiB` per stream, configurable in `ExecutionPolicy`) with explicit `stdout_truncated: bool` and `stderr_truncated: bool` flags so untrusted container output can never OOM the host `boxlet` process.
  - Observable policy-violation fields recorded in `ExecutionResult`: `timed_out: bool`, `oom_killed: bool` (read from cgroup v2 `memory.events` `oom_kill` counter before cgroup teardown), `exit_code: Option<i32>`, and `termination_signal: Option<i32>` (surfacing `SIGSYS` when seccomp uses `KILL_PROCESS`/`KILL_THREAD`). Note: `SCMP_ACT_ERRNO` (`EPERM`) seccomp denials are observed in-guest by the workload (and verified by our regression tests) rather than emitted out-of-band by the kernel to the parent runtime.
- **Module architecture:**
  - `src/policy.rs`: First-class `ExecutionPolicy` and `ExecutionResult` types (platform-agnostic, serde-serializable).
  - `src/traits.rs`: Replaceable boundaries: `RootfsProvider` (V1: bind-mount + `pivot_root`; V2: overlayfs snapshot/diff), `ResourceController` (V1: cgroup v2), and `IsolationBackend` (V1: Linux namespaces + caps + seccomp; future: `youki` or Firecracker/`libkrun`).
  - `src/oci/`: `oci-spec` loader, container state store (default root `/run/boxlet`, overridable via `--root <dir>`, storing `<root>/<id>/state.json` via atomic write-and-rename guarded by a per-container `flock`), and OCI lifecycle state machine (`Creating -> Created -> Running -> Stopped`).
  - `src/linux/`:
    - `namespaces.rs`: PID, mount, UTS, IPC, and (for `network = none`) network namespaces.
    - `rootfs.rs`: `pivot_root`, `/proc`, minimal `/dev` nodes, masked/readonly paths.
    - `cgroup_v2.rs`: Targets Linux 5.15+ unified cgroup v2 under a dedicated parent cgroup (default `/sys/fs/cgroup/boxlet.slice`, overridable via `--cgroup-parent`), enabling `+memory +cpu +pids` in `cgroup.subtree_control` on the parent slice so leaf container cgroups (`<parent>/<id>`) obey cgroup v2's no-internal-processes rule. Enforces `memory.max`, `cpu.max`, `pids.max`; reads `cpu.stat`, `memory.peak`, and `memory.events` before teardown; cleans up deterministically via `cgroup.kill` + `rmdir`.
    - `caps.rs`: `PR_SET_NO_NEW_PRIVS` + capability drop via `caps`.
    - `seccomp.rs`: Resolves OCI `linux.seccomp` syscall string names to architecture-specific numeric IDs on `x86_64` and `aarch64` via the pure-Rust `syscalls` crate, then compiles rules to BPF via `seccompiler::BpfProgram`. Fails closed with an explicit `BoxletError::UnsupportedSeccompRule` on any unknown syscall name for the target architecture or unsupported OCI seccomp operator/flag.
    - `init.rs`: Self-re-exec `boxlet __init` child handshake synced over a pipe + start FIFO for OCI `create`/`start` separation.
  - `src/engine.rs`: Shared `Engine` driving `create`, `start`, `state`, `kill`, `delete`, and high-level `run(bundle, policy) -> Result<ExecutionResult, BoxletError>`.
  - `src/main.rs`: Thin `clap` CLI exposing `--root`, `--cgroup-parent`, `create`, `start`, `state`, `kill`, `delete`, `run`, and hidden internal `__init`.
- **Why this wins for V1:** Zero C dependencies guarantees a fresh Linux box builds with `cargo build` alone; self-re-exec init avoids Rust multi-threaded `fork()` UB; single-crate layout delivers the V1 demo fastest while keeping every V2/V3 seam intact.

## Success Criteria

1. **OCI Lifecycle Compliance:** `boxlet create`, `start`, `state`, `kill`, and `delete` enforce valid state transitions and pass the targeted `oci-runtime-tools` lifecycle, namespace, rootfs, capabilities, cgroup v2, and seccomp tests on Linux.
2. **Isolation & Security Regression Suite:** Automated Linux tests prove:
   - Memory limit enforcement (`--memory 128m` triggers OOM kill on excessive allocation and reports `oom_killed = true` in `ExecutionResult`).
   - Prohibited syscall denial (seccomp blocks a forbidden syscall such as `ptrace` or `mount`, verified both via in-guest `EPERM` test and `KILL_PROCESS` -> `SIGSYS` signal reporting).
   - Output capture cap (flooding stdout beyond `max_output_bytes` sets `stdout_truncated = true` without OOMing the host `boxlet` process).
   - Dropped capabilities + `no_new_privs` verified inside the container via `/proc/self/status`.
   - Zero orphaned processes and zero leftover `<cgroup-parent>/<id>` directories after normal exit, OOM kill, timeout, and forced `kill`/`delete`.
3. **Threat Model Accuracy:** `docs/THREAT_MODEL.md` is rewritten to document Boxlet V1's single-host, root-required, shared-kernel threat model, trust boundaries, and explicit non-goals.
4. **Shared Crate Integration:** An external Rust example/test crate calls `boxlet::Engine::run(...)` directly (matching the CLI) and inspects structured `ExecutionResult` fields (exit code, bounded stdout/stderr, truncation flags, duration, peak memory, CPU usage, violation flags, cleanup status).
5. **Fresh-Linux Reproducibility:** A fresh Linux 5.15+ machine (and GitHub Actions `ubuntu-latest`) builds Boxlet with `cargo`, passes CI (`rustfmt`, `clippy -D warnings`, `cargo-audit`, unit tests, privileged integration + `oci-runtime-tools` tests), executes the documented demo, and reproduces the results.

Question D3:
D3: Lock the exact Linux `boxlet __init` PID-1 spawn, pre-execve ordering, and crash-rollback contract?
Project/branch/task: boxlet (main) - docs/designs/boxlet-v1-oci-runtime.md:70-75 (Section 1 Architecture Review, Finding E2).
ELI10: On Linux, calling `unshare(CLONE_NEWPID)` does not put your current process into the new PID namespace; only its first child becomes PID 1. Recommendation: Full Linux init invariant contract because it prevents the three most common Linux OCI runtime bugs with zero extra scope.
